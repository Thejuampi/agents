# Codex Adapter

Codex CLI (OpenAI) reads `AGENTS.md` for project guidance and loads custom agents from `.codex/agents/*.toml`.

## Automated install (copy + sync)

Run from this repo, pointing at the project where you use Codex:

```pwsh
make install-codex TARGET=C:/code/myproject
make sync-codex  TARGET=C:/code/myproject   # re-run after editing agents/*.md
make install-codex-global                  # personal agents + skills + legacy prompts
make uninstall   TARGET=C:/code/myproject
```

This generates one TOML file per agent under `<target>/.codex/agents/<name>.toml`:

```toml
# generated by 'make sync'; source: agents/planner.md
# Do not edit here; edit agents/planner.md and re-run: make sync-codex
# model left unset: no per-harness model ID pinned yet (plan.v3.md section 4, open decision 6).

name = "planner"
description = "Produce a decision-complete implementation plan ..."
model = ""
model_reasoning_effort = "max"
sandbox_mode = "read-only"
developer_instructions = '''
# Planner
...full markdown body...
'''
```

Re-running `sync-codex` overwrites these files with the latest `agents/*.md` content. The canonical text stays in `agents/*.md`; the TOML files are generated adapters.

### TOML key table (I9)

Every generated agent TOML carries these keys (plus `developer_instructions`, described below — together the full I9 set: `name`, `description`, `developer_instructions`, `model`, `model_reasoning_effort`, plus `sandbox_mode`). The installer fails loudly (`throw`) before writing anything if a source `agents/*.md` filename collides with a Codex built-in agent name (`default`, `worker`, `explorer` — task 3.2), instead of silently shadowing it.

| Key | Source | Notes |
| --- | --- | --- |
| `name` | `agents/<role>.md` filename | |
| `description` | First non-empty line under `## Purpose` in `agents/<role>.md` | |
| `model` | Left `""` (unset) | No per-harness model ID is pinned (§4 item 6 below is the open decision on whether to change this). |
| `model_reasoning_effort` | `Get-RoleMeta -Name <role>` → `effortLevel` | Single derivation from `tier` (D4/D5): `Highest`→`max`, `High`→`high`, `Mid`→`medium`. Never a per-role hand-picked value. `reviewer`/`qa`/`refiner` land on `high`; `orchestrator`/`planner`/`sensei` land on `max` (the model tier map's `Highest`); `builder`/`advisor`/`curator` land on `medium`. |
| `sandbox_mode` | `Get-CodexSandboxMode` in `install/codex.ps1` | See the dedicated section below. |

`developer_instructions` is embedded as a TOML literal multi-line string (`'''...'''`, no escaping needed) whenever safe, and falls back to a fully-escaped basic multi-line string (`"""..."""`) only when the source body itself contains a `'''` run or ends in a trailing `'` — both of which would otherwise corrupt or truncate the embedded body (fixes PP-E; task 3.5). Round-trip fidelity is asserted by parsing every generated `.toml` back and comparing `developer_instructions` byte-for-byte against the canonical `agents/<role>.md` body (`.TrimEnd()`'d) — not just "the file parses."

## Native surfaces (verified against developers.openai.com/codex)

- **Custom agents**: `.codex/agents/*.toml` (project) or `~/.codex/agents/*.toml` (personal). Required fields: `name`, `description`, `developer_instructions`. Optional: `sandbox_mode`, `model`, `model_reasoning_effort`, `nickname_candidates`, `mcp_servers`, `skills.config`.
- **Project guidance**: `AGENTS.md` at the repo root (and nested directories), read hierarchically. The target project owns its own `AGENTS.md`; this installer does not copy ours. See "AGENTS.md discovery, precedence, and byte cap" below.
- **Skills**: the global install creates `~/.agents/skills/<name>/SKILL.md` (repo-agnostic, discovered by Codex app/CLI/IDE surfaces). Personal custom agents live at `~/.codex/agents/<name>.toml`; project agents live at `<target>/.codex/agents/<name>.toml`. Skills work in app, CLI, and IDE; invoke them as `$<name>` or select them from the `/` menu.
- **Custom prompts**: the global-only `~/.codex/prompts/*.md` surface exposes Markdown prompts as `/prompts:<name>` in CLI and IDE. Codex has deprecated this surface in favor of skills, but still supports it. See "Deprecated: custom prompts" below.

## Invoking playbook commands in Codex

After `make install-codex-global` and a Codex restart, run this in any Codex surface:

```text
$plan-this
```

You can also type `/` and select **Plan This** from the skill list. In CLI and IDE, the legacy `/prompts:plan-this` form remains available. Bare custom slash names cannot be registered directly.

The generated skill asks Codex to spawn the matching custom agent, wait for it, and return its result.

## sandbox_mode

Derived per agent in `install/codex.ps1` (`Get-CodexSandboxMode`):

- `workspace-write`: `builder`, `qa`, `orchestrator`
- `read-only`: everything else

Edit that table to tune. Subagents inherit the parent session's sandbox unless overridden in the agent file.

### Stage 6 `qa` eligibility (hard) — task 3.6 decision

Black-box QA is E2E **Stage 6**. Codex must either:

1. **Enforce a write allowlist** so QA cannot mutate the product tree (session `qa/` + evidence temp only), **or**
2. Mark the runner **`stage6_unsupported` / `BLOCKED_ENV`** for that session — do **not** treat “unsandboxable residual” as an acceptable PASS path.

`workspace-write` for `qa` is **not** a license to patch product source. Product fixes go through Builder via `review/fix-package-qa-r{N}.md`. Docs read is allowed; product-source oracle is policy-forbidden (`agents/qa.md`). Prefer degraded-mode source-citation detect when path deny is inexpressible.

**Decision (task 3.6): kept `workspace-write` for `qa`, justified rather than narrowed.** QA's Stage 6 duties (`agents/qa.md`) genuinely need to *write*: `qa/plan.md`, `qa/findings*.md`, `qa/probe.md`, and evidence (screenshots/logs) under `.agents/workspace/tmp/e2e/<slug>/qa/**` plus an evidence temp dir. Codex's custom-agent TOML schema has no path-scoped write-allowlist field alongside `sandbox_mode` (only the flat `read-only` / `workspace-write` / `danger-full-access` grant), so narrowing `qa` to `read-only` would make it unable to persist its own required Stage 6 artifacts at all — a strictly worse outcome than the residual risk being managed. The actual product-tree write denial is therefore enforced at the **policy layer**, not the sandbox layer: `agents/qa.md`'s hard `MUST NOT` on product edits, backed by option 2 above (`BLOCKED_ENV`) as the standing fallback if a future, path-scoped Codex sandbox makes policy-only enforcement insufficient. `orchestrator` keeps `workspace-write` for the same reason (E2E session artifacts: `plan.vN`, retro, `session-registry.md`) — it does not write product source as part of its own duties either, but genuinely needs the session-artifact write path.

## Deprecated: custom prompts (task 3.3, F-12)

`~/.codex/prompts/*.md` (the `-Global` install's `/prompts:<name>` surface) is a **deprecated** Codex API — Codex's own docs say custom prompts are deprecated in favor of skills. This installer **keeps generating them for one more cycle**: every generated file now carries a one-line deprecation banner pointing at this section, and skills remain the primary, non-deprecated invocation path (`$<name>` or the `/` menu).

**Open decision for Juan (§4 item 1 of `plan.v3.md`):** keep generating `~/.codex/prompts/*.md` with the deprecation banner (current default), or drop the surface entirely next cycle. Not decided by this wave.

## `[agents]` global settings (task 3.4) — document only, never write

Codex's `~/.codex/config.toml` supports an `[agents]` table for session-wide agent behavior, including the cap on concurrently running agent threads — the natural home for this repo's own cap-3 concurrency rule (`agents/orchestrator.md` Stage 4). **This installer never writes `~/.codex/config.toml` (I10)** — paste this yourself:

```toml
# ~/.codex/config.toml
[agents]
max_concurrent_threads_per_session = 3
```

The installer does not write this; paste it yourself.

## AGENTS.md discovery, precedence, and byte cap (task 3.7)

- Codex reads `AGENTS.md` hierarchically from the project root down to the working directory, merging/overriding as it descends (closer files take precedence for the same guidance).
- **Byte cap:** `project_doc_max_bytes` defaults to 32 KiB (32 768 bytes) per file. This repo's own `AGENTS.md` is **2 399 bytes** as of this wave — about **30 369 bytes (~93%) of headroom** before truncation. No action needed today; re-check this number if `AGENTS.md` grows substantially.
- **Fallback filenames:** `project_doc_fallback_filenames` lets an operator list alternate filenames Codex should also treat as project guidance when `AGENTS.md` is absent from a directory (useful for repos with a pre-existing convention such as `CONVENTIONS.md`). This repo always has a root `AGENTS.md`, so it does not need a fallback list; not configured here.

## Skill discovery locations

- **Global**: `~/.agents/skills/<name>/SKILL.md` — read by Codex app, CLI, and IDE surfaces; not tied to any one repo checkout (F-2 fix: names the role, does not bake an absolute repo path except as a clearly-labelled in-repo fallback).
- **Custom agents (personal)**: `~/.codex/agents/<name>.toml`.
- **Custom agents (project)**: `<target>/.codex/agents/<name>.toml`.
- **Custom prompts (deprecated, personal only)**: `~/.codex/prompts/<name>.md`, invoked as `/prompts:<name>` — see the deprecation note above.

## DRY Rule

The canonical prompt stays in `agents/*.md`. Codex-specific TOML files are adapters only.

## Resume / session continuity

| Field | Value |
| --- | --- |
| **Spawn path** | Orchestrator (main Codex session running `$e2e` / skill) spawns leaf **custom agents** from `~/.codex/agents/*.toml` or project `.codex/agents/*.toml` (generated from `agents/*.md`). Skills under `~/.agents/skills/` invoke those agents. |
| **`resume_supported`** | **`false`** |
| **Why** | Codex custom-agent spawn is documented for one-shot / new agent runs. This playbook does **not** document a stable API to resume a prior agent session by id. Do **not** invent one. |
| **`session_ref`** | Unknown unless Codex surfaces a run id in your version; if visible, record it; else `none`. |
| **Dead session** | Assume dead when a new agent invocation is required and no live resume handle exists. |
| **When resume unsupported** | **`reconstituted`** per Global Continuity checklist (prior packages on disk) or **`cold_start_waived`** / **BLOCK**. Never silent cold start on a `depends_on` / Stage 5 edge. |

Continuity law is orchestrator-owned; this section is harness honesty only.
