template, the checker list, the extra-FN quotes, and the frozen reprints.

\section{Pattern classes}
\label{app:classes}

The 341 patterns are grouped into nine classes by what the closing message is
doing. A class name written with a trailing question mark marks a doubt, which
defers to the judge instead of deciding.

Two classes need an exception that is decided outside the patterns.
\texttt{ask} patterns are suppressed on long messages, because a long report
that ends in a courtesy question is a report, not a request for permission.
\texttt{wait?} patterns are suppressed when the transcript shows the agent is
waiting on work it launched itself.

\texttt{wait?} and \texttt{errand?} are written as doubts because they fire
below the base rate of the failure they look for. They raise the closing to
the judge and decide nothing on their own.

\section{The judge's instruction}
\label{app:prompt}

The judge's system prompt is a decision rule, not a persona. Its shape, in
order: one-word output; standing permission; a short \textsc{stop} list
(permission, a question the repo answers, a menu, a next step this agent
could take now, an errand, a conditional offer); a short \textsc{ok} list
(delivered work, a status of work already done, work already in flight, a
closed caveat); River Plate Spanish as finished; and a test in place of a
default: is there a concrete action this agent could take right now without
information only the developer has, with \textsc{ok} when unsure. The 9B
prompt that preceded it taught the dangling-step case as the common
\textsc{stop}. Qwen 3.8 treated status reports of in-flight work as that
case. The test stayed; the lecture did not.

The counterweight paragraph was added after the gate began punishing useful
warnings. It is the only part of the prompt that argues against the gate's own
purpose, and it is load-bearing.

\section{The grading rule}
\label{app:grading}

\begin{quote}
\ttfamily\small
for each logged block:\\
\hspace*{2em}find the blocked message in its transcript\\
\hspace*{2em}count tool calls until the user speaks again\\
\hspace*{2em}(a tool result is not the user speaking)\\
\hspace*{2em}fewer than 3 tool calls $\Rightarrow$ the block bought nothing\\
\\
for each pattern class:\\
\hspace*{2em}if it has 8 or more graded blocks\\
\hspace*{2em}and 70\% or more bought nothing:\\
\hspace*{4em}name it for demotion
\end{quote}

The threshold of three tool calls exists because a woken agent commonly reads
one or two files to re-establish context before deciding to stop again. Zero is
too strict and would count that re-orientation as work.

\section{Reproducing the numbers}
\label{app:repro}

Every table in this paper is produced by a script in the hook's own
repository, run against the transcripts on the developer's machine. The
corpus builder is the only one that calls the model; the rest read its stored
labels and are arithmetic, so they run in seconds and give the same answer
every time.

A number reproduces only against the corpus it was computed on. Five builds
appear in this paper and all five stay on disk, because a rebuild moves the
labels and a benchmark pointed at the newest file answers a different
question than the table it feeds. Every benchmark takes the file as its first
argument.

The corpus is versioned by keeping the file from each build, so a table can be
recomputed against the state it was written from. The builder takes about 13
minutes over the 766 closings of the current build on a consumer GPU,

ablation is three passes of the same shape. Nothing else here needs a GPU.



\section{The 3.8 system prompt}
\label{app:system}

The live instruction, in full:

\begin{quote}
\ttfamily\footnotesize
You label a coding agent's closing message. Reply with exactly one
word: STOP or OK.\\
The agent has standing permission to act and never needs to ask.\\
STOP = it asked permission, asked a question the repo answers,
offered a menu, named a next step it could take now, told the user
to run or check something, or made the work conditional on being
asked.\\
OK = it delivered what it was asked, reports finished work, or a
status of work already done while other jobs or agents continue.
Naming work already in flight is OK.\\
A useful warning about something already investigated is OK. Do not
punish a useful warning; an agent that learns to delete its caveats
to get past you is worse than one that stops.\\
The agent writes River Plate Spanish. Read these as finished, not as
something in progress: la app levanta / levanto (it starts and
runs), quedo cableado (it is wired end to end), anda / corre (it
works), lo saque (I removed it), quedo cerrado (it is closed).\\
The test is whether there is a concrete action the agent could take
right now, in this repository, without any information only the
developer has. If the only thing left needs the developer's answer,
their preference, or their priority, that is OK. If the agent could
have kept working and did not, that is STOP.\\
When unsure, answer OK.\\
/no\_think
\end{quote}

Fourteen shots follow. The contrast that 27B needed is the in-flight
\textsc{ok}:

\begin{quote}
\ttfamily\footnotesize
Wave 3 delivered and is accepted. QA returned PASS. R11--R13 are
still building in background. $\rightarrow$ OK
\end{quote}

The 9B prompt that preceded this one taught the dangling-step case as
the common \textsc{stop} on 21 shots. Qwen 3.8 treated status reports
of in-flight work as that case. The criterion stayed. The lecture
did not.

\section{Worked closings}
\label{app:cases}

These are live rows, shortened. They are here so a reader can see
what the tables compress.

\paragraph{A finished report with a closed caveat, \textsc{ok}.}
Done. 41 tests green, committed. Heads up: that test flakes when the
machine is low on memory. I traced it to the Gradle workers, not the
code. Running with \texttt{--max-workers=1} is green every time.
Blocking this teaches the agent to delete the warning.

\paragraph{A dangling next step, \textsc{stop}.}
13 tests verdes, el consenso guarda low/high/N. Lo que sigue: el
cliente de opciones de Yahoo y leer el periodo 0q de
\texttt{earningsTrend}. The work is named and available.

\paragraph{An answer, \textsc{ok}.}
User: ok como es la url? Agent: \texttt{http://127.0.0.1:11434}.
Without the asked prefix the judge reads a short message with no
work in it and stops the turn.

\paragraph{In-flight status, \textsc{ok} on 27B, extra fire on 9B.}
Wave 3 delivered and is accepted. QA returned PASS. R11--R13 are
still building in background. The 9B prompt called this a dangling
step. The 3.8 prompt calls it a status.

\paragraph{A wait instead of a look, extra miss on 27B.}
Full suite running in the background; I'll check the results when it
completes. No running tool call for the waiting lane to see. The
developer pushed. This is the recall the in-flight rule spent.

\paragraph{A social opening, extra fire on 27B.}
Bien, gracias. \textquestiondown En qu\'e te ayudo? Linguistically a
stop. The push label is quiet because the developer just said the
task. One-sided labels hide this row from precision.

\paragraph{Quoted text must not fire.}
A status report that pastes a table of ``next steps'' used to trip
\texttt{announce}. Fenced blocks, tables, backticks and quotation
marks are stripped before matching. This project's own reports
hit that bug twice.


\section{The fourteen shots}
\label{app:shots}

Each pair is a closing and a label. Asked prefixes sit in the
closing string when the gold needed them.

\begin{enumerate}[leftmargin=1.4em,itemsep=2pt]
\item An URL after ``ok como es la url?'' $\rightarrow$ \textsc{ok}.
An answer is not a stop.
\item ``I can generate it if you want.'' after ``y el reporte?''
$\rightarrow$ \textsc{stop}. A conditional offer.
\item ``Should I wire it up now?'' $\rightarrow$ \textsc{stop}.
\item ``Runs. 2090 tests, 0 failures. The card prints once.''
$\rightarrow$ \textsc{ok}.
\item ``Next up: wiring the report into the screen.''
$\rightarrow$ \textsc{stop}. A named next step.
\item ``Wave 3 delivered and is accepted. QA returned PASS.
R11--R13 are still building in background.'' $\rightarrow$ \textsc{ok}.
The contrast shot: status of in-flight work is not a dangling step.
\item ``Let me know and I will continue.'' $\rightarrow$ \textsc{stop}.
\item ``I found three possible approaches. Which do you prefer?''
$\rightarrow$ \textsc{stop}. A menu.
\item ``Fixed and pushed. The build passes on CI.'' $\rightarrow$ \textsc{ok}.
\item ``The file is ready but I have not run it yet.''
$\rightarrow$ \textsc{stop}. Work it could take now.
\item A Spanish dangling step that names the Yahoo client
$\rightarrow$ \textsc{stop}.
\item A finished report plus a closed Gradle-worker caveat
$\rightarrow$ \textsc{ok}.
\item ``Si te interesa alguno en serio, te busco benchmarks''
$\rightarrow$ \textsc{stop}. An errand offered, not taken.
\item ``Listo. Cerrado como pediste. El PR esta en github, mergeable.''
$\rightarrow$ \textsc{ok}.
\end{enumerate}

Fourteen is already a cut from 21. The 21-shot 9B prompt is what
27B over-generalized. Cutting further is a speed experiment, a
shorter prefix, and a quality risk.

\section{The checkers behind Lane 1}
\label{app:checkers}

The orchestrator in \texttt{check-stop.py} loads every
\texttt{check-*.py} beside it on each Stop. A checker that is sure
ends the evaluation. A checker that is only suspicious returns
\texttt{MAYBE} and its hit is carried into the judge. Adding a file
is the install. Sessions do not need a restart. The Stop spec both
harnesses load is \texttt{stop.json} beside that orchestrator.

\paragraph{\texttt{check-permission.py}.}
341 regular expressions in nine classes, plus \texttt{shape}
computed in code. Quoted text is stripped. Long reports suppress
\texttt{ask}. A running background task suppresses \texttt{wait}.
This is the volume lane.

\paragraph{\texttt{check-blocked.py}.}
Lane 0. A \texttt{BLOCKED:} closing is an escape hatch. No tool
call, four named blockers at once, or three consecutive blocked
closings fail the audit. The release phrase is generated per block
from a cryptographic source and lives in no file the agent can
read.

\paragraph{\texttt{check-cycle.py}.}
The same closing twice in a chain is a loop. The digest is of the
prose, not of the whole payload.

\paragraph{\texttt{check-dead-code.py}.}
A claim that code was removed, with the file still importing it.

\paragraph{\texttt{check-done-claim.py}.}
A delivery claim with no matching tool call in the turn.
Uncommitted \texttt{.md} and \texttt{.tex} count as source, so a
paper or README that moved with the code cannot stay uncommitted
behind a delivery claim.

\paragraph{\texttt{check-hollow.py}.}
A short acknowledgement that did no work.

\paragraph{\texttt{check-numbers.py}.}
A number the agent stated that the transcript contradicts.

\paragraph{\texttt{check-tree.py}.}
A scored option list next to the session as \texttt{decisions.json},
or at \texttt{.grok/decisions.json}. A failed path with a
higher-score sibling still open is leftover. A low-score node waits
unless it sits next to the node just processed. A closing that names
leftover options without a tree file still fires. On frozen v4 the
word leftover is 0 fires over 749 closings. The pick rule is seven
fixtures, zero wrong. \texttt{bench-tree.py} reprints both.
A loaded tree with no next path, and uncommitted source this session
wrote, is leftover. That is the case a \texttt{taken} tree used to hide.

Most of these fire rarely. Permission and shape do the work. The
rare checkers exist because a single ugly miss taught each one.

\section{Human misses the live patterns still leave}
\label{app:stillmiss}

Thirteen closings a person answered are still a push with no live
firm hit and a 27B \textsc{ok}. They are not one class.

\paragraph{The user said push.} The agent shipped a UI change or a
doc and stopped. The next message is ``push'', ``push and pr'',
``good push all changes''. Standing permission includes git. The
closing does not name the leftover, so a regex over the closing
cannot see it. The cheap skip would not have helped: there is
nothing to match.

\paragraph{The user said keep going on a report.} A PreReport
builder write-up, a crash post-mortem, an E2E round summary, an
LD-18 table. The developer answered ``seguí'', ``ok continue'',
``ok revisa una vez mas''. The label is one-sided: a finished
report can still be a stop if the standing order was to take the
next step. The 27B called them \textsc{ok}. A pattern that fires
on every long Spanish report would be the 9B extra-FP set.

\paragraph{Waiting on the app suite.} One closing, one push. The
broader ``Waiting on the'' family is three closings and one push.
It stays out.

\paragraph{Checking again shortly, without I'll.} One closing, one
push. That line now ships.

\paragraph{Sin cambios / No response requested.} Harness-shaped.
The second is already firm via shape and still an extra miss
because the 27B said \textsc{ok} and the stored firm flag on v4
was computed before later pattern edits. Live scoring still sees
some of them as firm.

\section{The cheap skip, four hours of wall time}
\label{app:cheap}

A working turn used to skip the judge at 400 characters and three tool
calls. That threshold released leftover work. The skip is now four
hours of wall time, and only when Lane 1 has no firm hit. The constant
is \texttt{STOP\_WORK\_SECS}, default 14400. Claude stamps the user
turn on the transcript. Grok stamps it as \texttt{turn\_started} in
\texttt{events.jsonl}. A missing clock does not skip. Firm leftover
still blocks. The 27B is not replaced.

\section{Prefill numbers from the timed sample}
\label{app:prefillnums}

Eleven closings, 4k and 8k context, first call and identical replay.
Context agreed on every pair (0 flips). First-call wall time is the
KV realloc when context switches, 23--35\,s. Replay is 0.43--0.80\,s,
which is the sequential re-judge once the prefix is warm. Decode is
under 0.4\,s in every row. Lengthening the closing from 58 characters
to 5{,}258 raises prompt tokens from 886 to 2{,}317 and first-call
prefill from 12\,s to 17\,s at 4k; the replay stays flat. The product
does not switch context, so a live stop after a warm prefix is the
replay column.

\subsection{How Grok pairs are read}
\label{app:grokread}

A Grok \texttt{chat\_history.jsonl} row is not a Claude transcript
row. \texttt{host.project\_grok} maps it:

\begin{itemize}
\item \texttt{reasoning} and \texttt{system} drop.
\item \texttt{synthetic\_reason} user rows drop.
\item \texttt{tool\_result} becomes a Claude tool result on the user
role, so \texttt{transcript.spoke} does not treat it as the developer.
\item Assistant text plus \texttt{tool\_calls} become Claude
\texttt{tool\_use} blocks. The tool names are the Claude names the
rest of the gate already knows (\texttt{Write}, \texttt{Edit},
\texttt{Bash}, \texttt{Task}).
\end{itemize}

The user body is not the raw Grok wrapper. A first user row can be a
multi-kilobyte dump of \texttt{user\_info}, skills, and MCP banners.
The extractor keeps the \texttt{user\_query} span and drops
\texttt{system-reminder} and \texttt{user\_info}. Without that cut,
\texttt{reply\_of} would hand the push judge a page of harness.

Wake rows that start with ``Stop hook feedback:'' increment
\texttt{blocks} and do not close the window. That is the same rule
the Claude walk has used since the first contaminated build.

\label{app:protocol}

A candidate regex is a string taken from an extra miss. It is
compiled case-insensitively and run on \texttt{unquoted} of every
clean v4 closing, the same function the live gate uses.

\begin{enumerate}
\item Count true positives (push and the regex hits).
\item Count false positives (no push and the regex hits).
\item Count extra false negatives recovered (push, the live file
missed it, the regex hits).
\item Ship only when false positives are 0 and extra false
negatives are at least 1, or when the phrase has zero hits on v4
and came from a Grok or Codex closing whose next line is a short
push.
\item A class-wide wait or announce line that sits below the base
rate stays a doubt even if one of its phrases would ship firm.
\end{enumerate}

That protocol is why \texttt{Waiting on the} stays out and
\texttt{stages closed} shipped at T1. T3 then shipped
\texttt{Waiting on the app} on the same bar: extra FN 1, FP 0.
Four wait phrases are firm. 33 wait lines stay doubts.

\subsection{Grok pair extraction, as code}
\label{app:walkpairs}

\texttt{corpus.py --expand} writes Grok pairs and does not touch
\texttt{corpus.json}. The walk is the Claude walk with one extra
argument: the user body is \texttt{grok\_body} instead of the raw
string.

\begin{verbatim}
QUERY = re.compile(r"<user_query>\s*(.*?)\s*</user_query>", re.S)

def grok_body(text):
    raw = str(text or "")
    found = QUERY.search(raw)
    if found:
        return found.group(1).strip()
    cleaned = DROP.sub(" ", raw)
    cleaned = re.sub(r"</?[^>]+>", " ", cleaned)
    return " ".join(cleaned.split())

def grok_pairs():
    home = os.environ.get("GROK_HOME") or os.path.join(
        os.path.expanduser("~"), ".grok")
    pattern = os.path.join(home, "sessions", "*", "*",
                           "chat_history.jsonl")
    out = []
    for path in sorted(glob.glob(pattern)):
        rows = list(host.entries(path))
        chunk = walk_pairs(rows, path, grok_body)
        for row in chunk:
            row["source"] = "grok"
        out.extend(chunk)
    return out
\end{verbatim}

before the Grok-facing lines: 95 of 253. After push-labelling, 46
of 253 are pushes.
